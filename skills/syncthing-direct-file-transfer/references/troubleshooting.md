# 按现象排查

先定位实例、连接、共享、文件这几层中的故障，不从一个报错直接跳到 NAT 或权限结论。

## 现象与下一步

| 现象 | 先检查 | 下一步与判断边界 |
|---|---|---|
| API 拒绝连接 | 目标实例是否存活，API 地址、端口及启动日志 | 实例未运行时先解决启动问题，不能据此判断 NAT 或防火墙；两个进程可能是监控父进程与子进程 |
| ID 正确但设备未连接 | 双方是否互加、设备是否暂停、当前发现地址及监听状态 | 查设备连接；未共享文件夹不能直接解释不拨号 |
| 换网后仍使用旧地址 | 执行主机、活动网卡、SSID、网关及发现缓存 | 读取最新 listener WAN 映射，必要时更新对端 endpoint 并保留 dynamic；避免反复重启改变映射 |
| 公网查询显示代理节点 | 查询工具和 Syncthing 各自的实际路径 | 按进程分流时结果可能不同，转到[代理分流](proxy-routing.md) |
| 分流规则未生效或保存后消失 | 实际内核、运行配置、规则顺序和持久设置位置 | 修正对应客户端的持久设置，再检查运行时命中；不要只改生成文件 |
| Windows 放行后仍不通 | 实际网卡的 Public/Private 配置文件及程序显式阻止规则 | 显式阻止优先于允许，见[Windows 进程与防火墙](platforms.md#windows-进程与防火墙) |
| Symmetric NAT / cannot punch | 日志采集时间、对应网络、当前 listener WAN 映射及可达入口 | NAT 标签是该次观测，不单独证明直连必定失败或唯一原因；有界尝试后检查入口或[换网复测](#换网复测)，不自动启用中继 |
| QUIC 报 no recent network activity | 双方是否向当前精确 WAN 端点拨号、接收是否有回应及代理证据 | 只证明本次拨号超时，不单独定位到 NAT、代理或防火墙；先排除旧映射，避免原样无限重试 |
| Port restricted NAT | 当前映射与真实对端连接 | 只是具备尝试条件，仍需实际连接与文件验证 |
| 已连接但进度 0% | 目录 ID、共享设备、是否接受目录、收发模式、暂停状态及索引 | 按文件夹层推进，不把设备在线当成文件已同步 |
| idle 且零文件 | 是否收到源索引、源端预期是否非空 | 用测试文件或源清单检查，不能直接验收 |
| Android 建目录失败或只读 | 完整路径是否误指根目录、是否夹杂文字、所选位置是否可写 | 先用[原生目录选择器](platforms.md#android-客户端接收)核对路径，再判断真实权限需求 |
| wait 超时 | 文件是否继续增长、地址是否陈旧、是否有传输错误 | 超时不表示后台已停止，按状态决定继续或更换网络 |

## NAT 与入口证据

- 独立 PowerShell/curl/STUN 探测只代表该工具的网络路径；按进程分流时不能替代 Syncthing 的出口证据，代理旁路参数也不能排除 TUN 接管。
- STUN 返回不同映射是诊断线索，不足以单独定性 NAT。结合 Syncthing 自身 NAT 日志、当前 listener WAN 映射和实际连接；没有 WAN 映射不能直接判定 STUN 未运行。
- UPnP 报告开口成功后，检查 external address 是否为可达公网地址。私网外部地址或多个 UPnP 设备的成功日志，不能证明已穿过上游 NAT。
- 本地监听端口与公网映射端口可以不同。QUIC 公网映射变化不要求本地新增同号监听或防火墙端口；手工转发应指向实际 LAN 地址及本地监听端口。UDP 映射不能直接用于 TCP。
- `Symmetric NAT` 是 Syncthing 在该时间和网络路径上的分类线索。此类 NAT 可能对不同目的端点使用不同映射，STUN 返回的 WAN 端点不保证对另一台设备可回拨；标签本身不能证明当次直连必定失败，也不能独立排除代理/防火墙或确定唯一原因。旧 NAT 日志需结合采集时间、当前网络和 listener 核对，换网后不能沿用旧分类。
- 对称 NAT 网络下的一次失败不能推导为所有网络或所有 P2P 工具均无法直连。替代入口包括一端公网转发、双方可达的全局 IPv6 或更换网络；仅有 `fe80::` 不能作为公网 IPv6 入口。

## 换网复测

两端服务运行、中继关闭、确认当前地址后，若有界尝试仍双向 QUIC 超时，先停止原样重复试探，选择补充精确流量证据或更换网络。优先让可操作的一端切回已成功过的网络；不为此关闭 TUN、切全局直连或重启代理。

换网后现场读取 listener 的新 WAN 端点，双方必要时运行时更新对端地址并保留 dynamic，不假定旧端口仍有效；发现缓存可能仍含旧网络地址。检查实际主/次连接均为 TCP/QUIC、无 relay，再在原独立测试目录刷新一个已知大小/源哈希的合成文件，避免旧文件或旧完成率冒充本轮传输。由接收端确认当前文件大小、SHA-256、idle、待收为零及无错误。无需重建设备身份或共享个人文件；此后的大文件仍按源清单验收。

实测案例：一端 Wi-Fi 最近的 Syncthing NAT 日志为 Symmetric NAT，双方当前 QUIC 端点均拨号超时。对方虽有 syncthing UDP 的 DIRECT 记录，但采样目的端口是本地默认同步端口，而实际拨号目标是不同的公网映射端口，该样本不能直接证明目标拨号命中 DIRECT。另一端仅能读取生成规则，运行时分流证据不足。

对方切回此前成功的网络，代理/TUN 保持不变，重新交换变化后的 QUIC 映射后建立公网 QUIC 连接。新 1 MiB 合成文件接收完成、双方 SHA-256 一致，接收端 idle、待收为零且无错误。此结果支持继续优先排查网络路径、NAT 映射及 UDP 可达性，但换网同时改变了映射、路由等条件，不是单变量因果实验；不能认定对称 NAT 是唯一原因，也不能据此断言原网络绝无直连可能，或未经采样就宣称新网络的 NAT 类型。

## 验收证据

| 层次 | 能支撑结论的证据 | 不能替代它的现象 |
|---|---|---|
| 配置 | 两端 `relaysEnabled=false`，显式 TCP/QUIC 监听，无 relay/default | 只修改了一端或只生成了配置 |
| 连接 | 当前双方实际 TCP/QUIC 主/次连接均无 relay，核对真实对端地址 | 设备 ID 正确或界面显示在线 |
| 代理路径 | 被接管的端核对同一时段、实际进程、协议、对端 IP 和目标端口的运行时策略及出口；未被接管的端说明依据 | 生成规则、其他进程/端口的命中、累计 hitCount 或未使用 Syncthing relay；详见[精确流量证据](proxy-routing.md#direct-证据边界) |
| 文件 | 接收端文件与源清单的名称、大小、SHA-256、目录树一致，索引完成且无错误 | 发送端完成、本地哈希单独计算、ZIP CRC 或已开始接收 |

一次连接结果只证明当时的链路。网络或配置变化后重新核对；只验证到接收开始时，不报告整批交付完成。没有源清单时明确未完成源文件级验收。
